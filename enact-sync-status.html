What the anchor count cannot see

These are the real constraints. Each one is a compile or test failure that a text-match check passes straight through.

high

Method::contract is arm-complete

upstream's contract() match covers the closed enum exhaustively — its own comment says a new method cannot be added without declaring what it accepts and returns. Adding the fork's SessionTools variant therefore does not compile until a contract arm is added in the same file. An anchor count cannot see this; the compiler does.

high

Method::ALL is the single wire table

wire_name() panics with "every variant is in ALL" if a variant is missing from the table, and from_wire() is a scan of that same table. The fork's session/tools entry has to land in the table, not only in the enum.

high

The schema catalog test is exclusive

every_typed_contract_resolves_to_a_schema_or_an_external_owner asserts a named contract type is EXACTLY ONE of catalog-defined or external. SessionToolsResult must therefore be added to the proto catalog (it is plain data, so upstream's own rule puts it in the protocol crate) — not left out.

medium

The overlay now patches a published crate

zeroclaw-rpc-proto is publish = true and its rpc_type! macro derives JsonSchema under schema-export, where the runtime's macro does not. The fork's added success field on the tool-result notification now participates in schema export, so the tracked OpenRPC document would drift if it were ever regenerated from a prepared tree.

medium

That drift is not caught by CI today

upstream's ci.yml runs cargo generate openrpc --check, but the fork's ci.yml triggers only on pull_request to master while the fork's default branch is enact/branding — so upstream's Quality Gate does not run here at all. Only Validate PR title, Apply path labels and the manual native build run. This is why the local test sweep is the real gate, and it is worth adding the OpenRPC check to the fork's own workflow.

high

The release gate check already fails today

AGENTS.md requires git diff --exit-code $upstream_base -- src crates Cargo.toml Cargo.lock with the base pinned in release.json. That check fails on the branch right now: release.json pins 1c1cd118 but the branch's core actually matches 06765b1e6, which is 75 upstream commits further on. This is pre-existing drift, not caused by the pending sync, and it must be fixed by re-pinning release.json during the sync.

medium

The distribution version has to move

The merge takes Cargo.toml to 0.9.0, so release.json's version has to move from 0.8.7-enact.2 to a 0.9.0-based one, and the upstreamCommit pin has to become the new upstream head. The published 0.8.7-enact.1 release and its withdrawn sibling stay untouched.

The plan

Follow upstream's structure — do not reshape its RPC types. Re-point the overlay onto the protocol crate and satisfy the two exhaustiveness constraints upstream imposes on its own method set.

  1. Merge upstream/master into the PR branch

    Already rehearsed in a scratch worktree: one conflict, web/package.json, resolved as a union — upstream's dependency bumps and its two new test entries, plus the fork's branding test. 146 files, +36,035 / −4,212.

  2. Re-point the four moved anchors at the protocol crate

    Follow upstream's structure rather than reshaping its RPC types: the enum variant and wire table move to zeroclaw-rpc-proto/src/method.rs, the payload anchors to zeroclaw-rpc-proto/src/types.rs, and SessionToolsResult is defined in the protocol crate with a catalog entry, matching upstream's own rule that plain wire data lives in the protocol crate.

  3. Add the contract arm and the catalog entry

    The part no anchor count finds: a Method::contract arm for SessionTools (the match is arm-complete) and SessionToolsResult in the proto schema catalog (the catalog test is exclusive).

  4. Re-pin release.json

    upstreamCommit becomes the new upstream head and the version moves to a 0.9.0-based one, which makes the documented core-match check pass again instead of failing as it does today.

  5. Re-run the whole gate

    Overlay gate, the cargo test sweep, cargo fmt, a release build and probe_native.py, then the native build workflow on all three platforms — because session/tools is asserted by the native fixture, so the fork's own method has to survive the move.

  6. Push and keep PR #4 open against enact/branding

    Never upstream. The convention is recorded in overlays/enact/AGENTS.md and in the enact-tools README.
